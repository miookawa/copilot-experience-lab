## 大阪出張の準備、全部やっておいて。｜CWK-11

| 項目 | 内容 |
|---|---|
| **目的** | 自分がログインしている宿泊予約サイトの予約履歴を起点に、複数の Web サイトを横断して出張の候補を集めさせ、比較表と稟議用の下書きまで、予約を伴わずに準備する |
| **所要** | 約 20 分（目安／Cowork の処理時間を含む） |
| **利用** | Microsoft 365 Copilot Cowork（ローカル ブラウザー / Outlook） |
| **入力** | **自分のアカウント・業務データ**：普段利用している宿泊予約サイトの予約履歴、出張の目的、日程、訪問先、1泊あたりの宿泊費の上限金額 |
| **成果** | 宿泊・移動の候補比較表（チャット内） → 上限金額との照合結果 → 上長宛ての稟議メール下書き（**送信しない**） |

> **実施条件**：Copilot Cowork のローカル ブラウザー機能が利用できる場合にハンズオンで実施します。
> そうでない場合は、ファシリテーターのデモを見ながら進めてください。
> **この演習では、予約・購入・送信は一切行いません。** 候補の収集と比較までに限定します。
> **この演習は、参加者自身のアカウントで実施します。** 予約履歴は個人情報のため、**参加者の画面は投影しないでください。** デモはファシリテーター自身のアカウントで行います。
> **社外の一般サイトを対象とするため、表示内容やサイト構成の変更により結果が変わることがあります。** 実施前に一度、同じ手順で動作を確認しておいてください。
>
> **クレジット消費の目安**：`Medium`（`[要記入]〜[要記入]` クレジット）。この演習の参考区分です。実際の消費量は、対象データの量・形式・内容や依頼する処理によって変動します。
> Light / Medium / Heavy の区分は、Microsoft の [Copilot Credits Guide](https://www.microsoft.com/licensing/guidance/Copilot-Credits) で使われている表現に基づきます。

## 事前準備

### ファシリテーター（開始前に完了させておく）

- 乗換案内サイトを **1 件に決めておく**
- 自分のアカウントで当日と同じ条件で一度実行し、次を確認しておく
  - 予約履歴の画面を Cowork が読み取れること
  - サイトが正常に表示されること
  - ログインを求められたときに、「対応が必要です」→「ログイン」→パスワード入力→「完了しました」の流れで続きが進むこと（当日はこの画面をデモで見せると、参加者が迷いません）
  - 履歴にキャンセル済みの予約などが混ざる場合の表示
- 参加者に、事前準備（下記）と「画面を投影しないこと」を案内しておく

### 参加者（開始前に完了させておく）

- 端末の **Microsoft Edge で、普段利用している宿泊予約サイトにログインしておく**
  - Cowork は、このログイン状態をそのまま使って操作します。パスワードを Cowork に渡す必要はありません
  - ただし、予約履歴を開くときにパスワードの再入力を求められることがあります。**パスワードをすぐに入力できるようにしておいてください**
- 予約履歴に今回の出張先都市の宿がなくても進められます（その都市で新しい候補を 3 件探します）

## シナリオ

あなたは、来月に大阪への出張を予定している営業部門のマネージャーです。

出張を決めるまでに、次のことを調べる必要があります。

- 以前泊まった宿の中に、訪問先まで近く、上限金額内で泊まれるところはあるか
- 移動時間と乗り継ぎはどうなるか
- 候補を比較して、上長に何を承認してもらうか

これまでは、宿泊予約サイトにログインして予約履歴を見返し、宿ごとに乗換を調べ、空室と価格を確認し直し、最後に比較表を作って稟議メールを書いていました。**調べること自体は難しくありませんが、画面を行き来する時間がかかります。**

この体験では、1 回の依頼で、自分の予約履歴を起点に複数の Web サイトを横断して候補を集めさせ、上限金額と照合し、比較表と稟議メールの下書きまで作らせます。**予約はしません。送信もしません。**

> **演習のポイント**：Cowork は、**あなたがログインしているブラウザーを、あなたの代わりに操作します。** そのため、Copilot Chat の Web 検索では届かない「**ログインしないと見えない情報（自分の予約履歴）**」を起点に調べられます。さらに、その結果が**宿泊費の上限金額と照合され、比較表とメール下書きまで一気に仕上がること**にも注目してください。

| | Copilot Chat | Cowork（ブラウザー操作） |
|---|---|---|
| 公開情報の検索 | ○ | ○ |
| 日付・人数などの条件入力、絞り込み | × | ○ |
| ログイン後にしか見えない情報（予約履歴など） | × | ○ |
| 上限金額と照合し、比較表・メール下書きまで作る | △ | ○ |

> **進行役の説明例**：「今日は、調べる作業そのものを渡します。皆さんがログインしているサイトで予約履歴を見て、乗換を調べ、空室と価格を確認し、比較表にして、稟議の下書きまで。予約も送信もしないので、安心して見ていてください。」

> **ローカル ブラウザーについて**：Cowork のローカル ブラウザー機能は、端末上の Microsoft Edge にある既存のサインイン、Cookie、セッションを使い、非表示のタブで操作を実行します。**Cowork が持つアクセス権は、利用者自身のアクセス権を超えません。** パスワードを AI に渡すのではなく、ログイン済みのブラウザーを利用者の代わりに操作します。

## TRY — 手順

1. **（比較）** Copilot Chat に「[出張先都市] で以前泊まったホテルの中から、[訪問先（社名・住所）] まで 30 分以内のところを教えて」と依頼し、どこまで答えられるかを見る（2 分程度）
2. Edge で、普段利用している宿泊予約サイトにログインしていることを確認する
3. Copilot Cowork を開き、次のプロンプトを貼り付ける。**置き換えるのは冒頭の【条件】にある `[ ]` だけ**です

   ```text
   次の条件で出張を検討しています。

   【条件】
   ・日程：[日付] から [泊数] 泊
   ・出張先都市：[出張先都市]
   ・訪問先：[訪問先（社名・住所）]
   ・宿泊予約サイト：[宿泊予約サイト名]
   ・乗換案内サイト：[乗換案内サイト名]
   ・1泊の上限金額：[上限金額] 円

   【依頼】
   1. 宿泊予約サイトの私の予約履歴から、出張先都市で過去に泊まった宿を
      直近5件まで一覧にしてください。
   2. それぞれの宿について、乗換案内サイトで訪問先までの公共交通での
      所要時間を調べ、30分以内の宿だけを残してください。
   3. 残った宿について、宿泊予約サイトで日程の空室と1泊の価格を確認し、
      上限金額を超える宿は「上限超過」と記載してください。
   4. 予約履歴に出張先都市の宿がない場合、または条件に合う宿が3件に満たない場合は、
      宿泊予約サイトで同じ条件（30分以内・上限金額以内）の新しい候補を探し、
      合計3件にしてください。

   結果は、宿名、過去の宿泊有無、所要時間、経路、価格、上限金額との適合が
   比較できる表にして、このチャットで示してください。
   その上で、上長に承認を依頼するメールの下書きを作成してください。

   予約はしないでください。メールも送信せず、下書きのまま残してください。
   確認できない情報は推測せず、そのように記載してください。
   ```

   > `[宿泊予約サイト名]` には、**各自が普段利用していて、ログインしている宿泊予約サイト**の名前を入れてください。

4. **送信**を選ぶ（処理には数分かかります）
5. **ログインを求められたら、自分でログインする**
   - Edge でログイン済みでも、予約履歴を開くときにパスワードの再入力を求められることがあります。その場合、チャットに「**対応が必要です**」という表示が出て、処理が止まります
   - 「**ログイン**」を選ぶと、右側にブラウザー画面（宿泊予約サイトのログイン画面）が表示されます
   - パスワードを**自分で**入力してログインを完了し、チャットの「**完了しました**」を選ぶと、続きから処理が再開します
   - パスワードをチャットに書き込む必要はありません。**Cowork がパスワードを扱うのではなく、本人がログインした状態を使って続きを進める**ことを確認してください
6. 処理中の表示を見る。予約履歴を開く → 宿の一覧を読み取る → 乗換案内で宿ごとに所要時間を調べる → 宿泊予約サイトに戻って空室と価格を確認する → 上限金額と照合する → チャットに比較表を表示 → メール下書き作成、と**画面が切り替わりながら進むこと**を確認する
7. チャットに表示された比較表で、次を確認する
   - 予約履歴から拾われた宿が「過去の宿泊有無」で区別されているか
   - 30 分以内の宿だけが残り、価格と所要時間が入っているか
   - 上限金額との適合が判定されているか
   - **サイトに表示されていない情報が作られていないか**
8. **候補を 1 件選び、実際にサイトを開いて価格と条件を照合する**（価格は変動します。取得時点の値であることを確認してください）
9. メールの下書きを開き、**送信されず下書きのまま残っていること**を確認する
10. 条件を変えて、もう一度依頼する

    ```text
    価格よりも、訪問先までの移動時間を優先して候補を選び直して。
    ```

11. 推奨の順位が変わったことを確認し、**何を優先するかで結論が変わる**ことを全員で共有する（共有するのは結果の傾向にとどめ、個人の予約履歴は見せ合わないでください）

> **注意**：Web サイトの表示価格、空室状況、所要時間は常に変動します。取得された情報は**その時点のもの**であり、実際の予約時には必ず本人がサイト上で再確認してください。予約、決済、キャンセル条件の判断は人が行ってください。

## REFLECT — 振り返り

- Copilot Chat では答えられず、Cowork だから使えた情報は何でしたか
- あなたが自分で開いたサイトはいくつでしたか。Cowork が開いたのはいくつでしたか
- 手作業で行う場合、予約履歴の見返し、宿ごとの乗換確認、空室・価格の再確認、比較表作成のどこに最も時間がかかりますか
- 取得した価格を上限金額と照合したことで、Web 検索だけの結果と何が変わりましたか
- 優先条件を変えたとき、推奨はどう変わりましたか。それは納得できる変化でしたか
- 取得された情報のうち、実行前に人が再確認すべきものはどれですか
- 普段ログインして使っているサイトのうち、同じように任せたい作業はどれですか（例：会場探し、備品の調達比較、購入履歴からの再発注候補づくり）

### うまく動かない場合

- 予約履歴が読み取れない場合は、Edge で宿泊予約サイトにログインし直してから、もう一度依頼してください。
- 予約履歴に `[出張先都市]` の宿がないのに新しい候補が出てこない場合は、「予約履歴は使わず、[出張先都市] で候補を3件探して」と依頼し直してください。
- 処理に時間がかかりすぎる場合は、「直近5件まで」を「直近3件まで」に減らしてください。
- ログインや認証確認の画面が出て処理が止まった場合は、手順 5 のとおり、右側のブラウザー画面で自分でログインし、「完了しました」を選んでください。「完了しました」が見当たらない場合は、チャットに「ログインした」と送れば続きが進みます。ログインできない場合は、ファシリテーターのデモに切り替えてください。
- 候補が出てこない場合は、条件（価格上限、所要時間）を緩めてください。
- 比較表の項目が足りない場合は、必要な項目名をプロンプトに列挙してください。
- 情報が古い、または不正確な場合は、該当箇所を指定して「サイトで再確認して、取得できない場合はそう記載して」と指示してください。
