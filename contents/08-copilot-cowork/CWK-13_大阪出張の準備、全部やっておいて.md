## 大阪出張の準備、全部やっておいて。｜CWK-13

| 項目 | 内容 |
|---|---|
| **目的** | 複数の一般 Web サイトを横断して出張の候補を集めさせ、比較表と稟議用の下書きまで、予約を伴わずに準備する |
| **所要** | 約 20 分（目安／Cowork の処理時間を含む） |
| **利用** | Microsoft 365 Copilot Cowork（ローカル ブラウザー / Excel / Outlook） |
| **入力** | **自分の業務データまたはサンプルデータ**：出張の目的、日程、訪問先、社内の出張規程（宿泊費上限など） |
| **成果** | 宿泊・移動の候補比較表（Excel） → 規程との照合結果 → 上長宛ての稟議メール下書き（**送信しない**） |

> **実施条件**：Copilot Cowork のローカル ブラウザー機能が利用できる場合にハンズオンで実施します。
> そうでない場合は、ファシリテーターのデモを見ながら進めてください。
> **この演習では、予約・購入・送信は一切行いません。** 候補の収集と比較までに限定します。
> **社外の一般サイトを対象とするため、表示内容やサイト構成の変更により結果が変わることがあります。** 実施前に一度、同じ手順で動作を確認しておいてください。
>
> **クレジット消費の目安**：`Medium`（`[要記入]〜[要記入]` クレジット）。この演習の参考区分です。実際の消費量は、対象データの量・形式・内容や依頼する処理によって変動します。
> Light / Medium / Heavy の区分は、Microsoft の [Copilot Credits Guide](https://www.microsoft.com/licensing/guidance/Copilot-Credits) で使われている表現に基づきます。

## 事前準備（ファシリテーター、開始前に完了させておく）

- 参加者が利用する宿泊予約サイトと乗換案内サイトを **2〜3 件に決めておく**（例：宿泊予約サイト 1〜2 件、乗換案内 1 件）
- **演習用のアカウントで実施するか、サインインせずに実施するかを決めておく**。
- 宿泊費上限や対象費目を記載した、1 ページ程度の出張規程サンプルを用意する
- 当日と同じ条件で一度実行し、サイトが正常に表示されること、認証確認の画面が出ないことを確認しておく

## シナリオ

あなたは、来月に大阪への出張を予定している営業部門のマネージャーです。

出張を決めるまでに、次のことを調べる必要があります。

- 訪問先の近くに、規程内の価格で泊まれる宿泊先はあるか
- 移動時間と乗り継ぎはどうなるか
- 候補を比較して、上長に何を承認してもらうか

これまでは、予約サイトをいくつも開き、条件を入れ直し、価格と立地をメモし、乗換を調べ、最後に比較表を作って稟議メールを書いていました。**調べること自体は難しくありませんが、画面を行き来する時間がかかります。**

この体験では、1 回の依頼で、複数の Web サイトを横断して候補を集めさせ、規程と照合し、比較表と稟議メールの下書きまで作らせます。**予約はしません。送信もしません。**

> **演習のポイント**：Cowork が実際にブラウザーを操作して情報を集めていることと、**その結果が社内の規程と突き合わされていること**の両方に注目してください。Web 検索だけでは、規程との照合までは進みません。

> **進行役の説明例**：「今日は、調べる作業そのものを渡します。サイトを開いて条件を入れ、結果を読み、比較表にして、稟議の下書きまで。予約も送信もしないので、安心して見ていてください。」

> **ローカル ブラウザーについて**：Cowork のローカル ブラウザー機能は、端末上の Microsoft Edge にある既存のサインイン、Cookie、セッションを使い、非表示のタブで操作を実行します。**Cowork が持つアクセス権は、利用者自身のアクセス権を超えません。**

## TRY — 手順

1. 対象とする宿泊予約サイトと乗換案内サイトを確認する
2. 出張規程（宿泊費上限など）の所在を確認する
3. Copilot Cowork を開き、次のプロンプトを `[ ]` を置き換えて貼り付ける

```text
[日付] から [泊数] 泊の [出張先] 出張を検討しています。
訪問先は [訪問先] です。

[宿泊予約サイト名] で、訪問先まで公共交通で30分以内、
1泊 [上限金額] 円以内の宿泊候補を3件探してください。

あわせて [乗換案内サイト名] で、
[出発地] からの往復の所要時間と経路を確認してください。

結果を、宿泊先、価格、訪問先までの所要時間、
移動経路、規程との適合を比較できるExcelにまとめてください。

その上で、上長へ承認を依頼するメールの下書きを作成してください。

予約はしないでください。メールも送信せず、下書きのまま残してください。
確認できない情報は推測せず、そのように記載してください。
```

4. **送信**を選ぶ（処理には数分かかります）
5. 処理中の表示を見る。サイトを開く → 条件を入力する → 結果を読み取る → 別サイトへ移動する → 規程と照合する → Excel 作成 → メール下書き作成、と**画面が切り替わりながら進むこと**を全員で確認する
6. 作成された Excel を開き、次を確認する
   - 宿泊候補が 3 件あり、価格と所要時間が入っているか
   - 規程の上限との適合が判定されているか
   - **サイトに表示されていない情報が作られていないか**
7. **候補を 1 件選び、実際にサイトを開いて価格と条件を照合する**（価格は変動します。取得時点の値であることを確認してください）
8. メールの下書きを開き、**送信されず下書きのまま残っていること**を確認する
9. 条件を変えて、もう一度依頼する

```text
価格よりも、訪問先までの移動時間を優先して候補を選び直して。
```

10. 推奨の順位が変わったことを確認し、**何を優先するかで結論が変わる**ことを全員で共有する

> **注意**：Web サイトの表示価格、空室状況、所要時間は常に変動します。取得された情報は**その時点のもの**であり、実際の予約時には必ず本人がサイト上で再確認してください。予約、決済、キャンセル条件の判断は人が行ってください。

## REFLECT — 振り返り

- あなたが自分で開いたサイトはいくつでしたか。Cowork が開いたのはいくつでしたか
- 手作業で行う場合、条件入力、結果の読み取り、サイト間の移動、比較表作成のどこに最も時間がかかりますか
- Web の情報と社内規程を突き合わせたことで、Web 検索だけの結果と何が変わりましたか
- 優先条件を変えたとき、推奨はどう変わりましたか。それは納得できる変化でしたか
- 取得された情報のうち、実行前に人が再確認すべきものはどれですか
- 同じ進め方を、会場探し、備品の調達比較、競合の公開情報の収集に応用できますか

### うまく動かない場合

- サイトが開かない、または結果が取得できない場合は、対象サイトを 1 件に減らしてください。
- 認証確認の画面が表示された場合は、その時点で操作が止まります。別のサイトへ切り替えるか、ファシリテーターのデモに切り替えてください。
- 候補が出てこない場合は、条件（価格上限、所要時間）を緩めてください。
- 比較表の項目が足りない場合は、必要な列名をプロンプトに列挙してください。
- 情報が古い、または不正確な場合は、該当箇所を指定して「サイトで再確認して、取得できない場合はそう記載して」と指示してください。
