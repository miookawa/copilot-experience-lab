# 提案書作成エージェントを作る｜AGB-05

| 項目 | 内容 |
|---|---|
| **目的** | 提案書作成という繰り返し業務を、より強い初稿を出すエージェントにまとめる |
| **所要** | 約 15 分（目安） |
| **利用** | Agent Builder |
| **入力** | エージェント名・説明・指示・スターター プロンプト（＋許可されたナレッジ ソース） |
| **成果** | 動作する「Proposal Assistant」 |

> **実施条件**：時間があれば実施する 2 つ目のエージェント作成です。

---

## シナリオ

松吉さんのパートナー連携部と大沢さんのマーケティング部は、ディスカバリー メモ、パートナー提案、キャンペーン案、サービス情報を、構造化された提案ドラフトに変える作業をよく行っています。

この作業は繰り返しが多い一方で、最終アウトプットは**正確性、スコープ、法務条件、価格、顧客の準備状況について人によるレビュー**が必要です。

そこでレイクショアは、**より強い初稿を出しつつ、最終承認の責任はビジネス オーナーに残す** Proposal Assistant を作ります。

---

## TRY — 手順

1. 時間があれば、2 つ目のエージェントを作成する
2. エージェント名に次を使う

```text
Proposal Assistant
```

3. 説明に次を使う

```text
メモ、顧客の背景情報、パートナーの要件、サービス情報を、提案ドラフト、SOW の骨子、
エグゼクティブ サマリーに変えるのを支援します。
```

4. ナレッジ ソースは、適切かつ許可されている場合にのみ追加する
   （例：`northwind-outfitters-proposal.docx`、`agent-knowledge-pack.docx`）
5. 指示（インストラクション）に次を使う

```text
あなたは SMB 向け組織の提案書アシスタントです。
ユーザーが明確で顧客に出せる提案コンテンツを作成するのを支援してください。

回答は次の構成にしてください:
エグゼクティブ サマリー、顧客の課題、提案するソリューション、ビジネス価値、スコープ、
スケジュール、責任分担、リスク、前提条件、次のステップ。

必要に応じて、不足している情報を尋ねてください。
トーンはプロフェッショナル、簡潔、実務的に保ってください。

価格、法務条件、納品のコミットメント、顧客の承認を創作してはいけません。
前提条件と、人によるレビューが必要な項目は明確に示してください。
```

6. スターター プロンプトに次を追加する

```text
- これらのメモを [顧客／プロジェクト] 向けの提案骨子にしてください。
- [提供内容／サービス] に関する提案のエグゼクティブ サマリーを作成してください。
- 次の情報を使って作業範囲記述書（SOW）の骨子を作成してください: [詳細を貼り付け]
- この提案ドラフトをレビューし、抜け、リスク、前提条件、不明瞭な箇所を特定してください。
```

7. エージェントを保存／作成する
8. 次の安全なシナリオでテストする

```text
次のメモを提案骨子にしてください:

レイクショアは、ノースウィンド アウトフィッターズとの 4 週間のスプリングアウトドア共同マーケティング
キャンペーンを検討しています。キャンペーンには、ホームページ掲載、ロイヤルティ メール、
有料ソーシャル、店舗サイネージ、店舗スタッフ トレーニングが含まれます。
ノースウィンドは有料ソーシャル費用の一部を負担する可能性がありますが、
最終的な在庫コミットメントと効果測定の詳細が不足しています。

エグゼクティブ サマリー、スコープ、責任分担、リスク、前提条件、次のステップを含む
提案骨子を作成してください。
```

9. 出力を、正確性、スコープの明確さ、抜けている前提、顧客に出せる状態かどうかの観点でレビューする

## REFLECT — 振り返り

- 「価格・法務条件・納品コミットメント・顧客承認を創作しない」という制約は、実務でなぜ重要か
- エージェントが**前提条件と要レビュー項目を明示する**ことは、レビュー担当者にどう効くか
- [CHAT-04](../01-copilot-chat/CHAT-04_パートナー提案書を要約し確認すべき質問を洗い出す.md) の提案書要約と組み合わせると、どんな業務フローが作れるか
