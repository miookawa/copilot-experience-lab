| 項目 | 内容 |
|---|---|
| **目的** | 繰り返し業務を、指示を書いたエージェントとして固定する |
| **所要** | 約 25 分（目安／ナレッジを登録しない場合は 20 分） |
| **利用** | Copilot の Agent Builder（インストラクション ＋ ナレッジ ソース） |
| **入力** | AGB-01 で選んだ繰り返し業務 1 件 ＋ 社内用語集ファイル（Word / Excel / PDF など。任意） |
| **成果** | 自分用の軽量エージェント 1 つ（インストラクション ＋ 登録したナレッジ） |

> **実施条件**：Agent の作成・共有可否、および登録できるナレッジ ソースの種類は、管理者設定、テナント構成、ライセンスによって異なります。実施前に管理者またはライセンス専門家に確認してください。
> 作成できない場合は、ファシリテーターのデモを見ながらインストラクションの書き方だけを持ち帰ってください。
> ナレッジ ソースが使えない場合も、ステップ 2 を飛ばしてステップ 1・3 だけで完結します。

## シナリオ

[繰り返し業務を洗い出して1件に絞る｜AGB-01](./AGB-01_繰り返し業務を洗い出して1件に絞る.md) で決めた業務を、エージェントとして固定します。

候補としては、次のようなものが扱いやすいです。① 社内用語を維持した日英翻訳エージェント ② 会議メモを決定事項とアクションに変換するエージェント ③ ホワイトボード写真から構造化された資料案を作るエージェント ④ 社内の特定ガイドラインについて回答するエージェント ⑤ 定型文書をルールに沿ってレビューするエージェント。

以下は、**① を例にしたインストラクションの書き方**です。自分が選んだ業務が ①〜⑤ のどれであっても、書き方の型は同じです。「役割 → 出力の順序 → やってはいけないこと」の 3 段で書きます。

> ③ を選んだ方は、[ホワイトボード写真から議事録とスライドを作る｜AGB-03](./AGB-03_ホワイトボード写真から議事録とスライドを作る.md) で 1 日かけて深掘りします。ここでは別の候補で型を覚えてください。

翻訳を例にしたのは、**AI がいちばん勝手に補完したがるのが「用語」だから**です。社内略語や製品名を黙って展開されると、翻訳文は読めるのに業務では使えません。

そこで今日は、指示を書くだけで終わらせません。**社内用語集のファイルをナレッジ ソースとして登録**し、指示（ルール）と辞書（ナレッジ）を組み合わせます。今日の見どころは、訳文の品質ではなく、**用語集どおりに訳し、載っていない語は「分からない」と言えるか**です。

> 進行役の説明例：「エージェントの出来より、『推測させない』指示が書けているかを見てください。」

## TRY — 手順

### ステップ 1 — エージェントを作る

1. Agent Builder を開く（利用可否は事前に管理者へ確認）
2. AGB-01 で選んだ業務を 1 つ決める
3. エージェントの名前を決める（例：`社内文書の日英翻訳`）
4. 説明を入力する（例：`社内用語集に沿って、社内文書を日英翻訳します`）
5. インストラクション欄をクリックし、次のインストラクション例を貼り付けて、自分の業務に合わせて書き換える

> **インストラクション例（候補①：社内用語を維持した日英翻訳）**

```text
あなたは社内文書の日英翻訳エージェントです。
ユーザーが渡した日本語または英語の文章を、もう一方の言語に翻訳します。

【最優先のルール】
- 用語の訳し方は、ナレッジとして登録された社内用語集に必ず従ってください。
- 用語集にある語は、用語集の訳語をそのまま使ってください。言い換えないでください。
- 用語集にない語は、翻訳せず原文の表記のまま残し、「用語集に未登録」と記載してください。
- 用語集にない語を、一般的な知識で補って訳さないでください。

【出力の順序】
1. 翻訳文
2. 用語集を適用した箇所の一覧（原語 → 訳語）
3. 原文のまま残した用語の一覧（「用語集に未登録」か「判断できず」かを明記）
4. 訳し方に迷った箇所の一覧（候補訳を2つまでと、判断に必要な情報）

【翻訳のルール】
- 製品名、サービス名、チーム名、社内で使われている略語は、
  翻訳せず原文の表記のまま残してください。
- 意味が確定できない略語を、勝手に展開しないでください。
  例：「SA」を「Solution Architect」と断定しない。
- 原文にない情報を足さないでください。省略もしないでください。
- 箇条書き、見出し、番号は、原文の構造のまま保ってください。
- 敬語や丁寧さの度合いは原文に合わせてください。
  勝手に丁寧にしたり、くだけさせたりしないでください。

【口調】
- 補足の説明、感想、励ましは書かないでください。
```

### ステップ 2 — 社内用語集をナレッジとして登録する

6. 手元の社内用語集ファイルを 1 点用意する（Word / Excel / PDF など）
   - 手元にない場合は、下の「用語集がない場合」を先に実施してください
7. Agent Builder の**ナレッジ**（知識）セクションを開く
8. 用語集ファイルを追加する
   - OneDrive / SharePoint 上のファイルを指定するか、手元のファイルをアップロードする
   - 追加できるソースの種類は、テナント構成とライセンスによって異なります
9. ファイルが登録済みとして表示されていることを確認する
10. エージェントを保存する

> **用語集がない場合**：Copilot Chat（Work）で次のように依頼し、出てきた表を Word に貼り付けて保存すれば、そのまま用語集として使えます。
>
> ```text
> 私の最近のメールと資料でよく使われている社内略語・製品名・チーム名を20語まで抜き出し、
> 「原語 / 読み方 / 英語表記 / 訳さずそのまま使うか」の4列の表にしてください。
> 確信が持てないものは「要確認」と記載してください。
> ```
>
> 20 語あれば、翻訳エージェントの出力は十分変わります。完璧な用語集を作ることは今日の目的ではありません。

### ステップ 3 — 動かして、直す

11. 実際の入力（自分の業務で使っている文章やメモ）を渡して動かす
12. 「用語集を適用した箇所」の一覧を先に読み、用語集どおりの訳語になっているかを確認する
13. 推測して補完された箇所がないかを確認する
    - 用語集にない語が、勝手に一般的な訳語へ置き換えられていないか
    - 「用語集に未登録」と正直に返ってきているか
14. インストラクションまたは用語集を修正して、もう一度動かす
15. 共有可否を管理者ポリシーに沿って確認する

> **書き換えのヒント**：①以外を選んだ場合も、`【出力の順序】` と `【〜のルール】` の枠はそのまま使えます。ルール欄には「**やってほしいこと**」ではなく「**やってはいけないこと**」を書くと、出力が安定します。

> **ナレッジの使いどころ**：ナレッジは①以外でも効きます。④なら社内ガイドライン、⑤ならレビュー基準やスタイルガイド、②なら議事録のテンプレートを登録します。ポイントは、手順書そのものより **判断基準が書かれたファイル** を渡すことです。

> **注意**：登録したナレッジの内容は、そのままエージェントの回答に使われます。用語集ファイルの取り扱い区分と、エージェントの共有範囲を必ず確認してください。自分だけで使う場合も、登録前に確認します。

> **注意**：Agent の作成・共有可否や利用できる機能は、管理者設定、テナント構成、ライセンスによって異なります。公式ガイドでも、エージェントには利用可能な種類、共有ポリシー、管理設定があると案内されています。

## REFLECT — 振り返り

- 毎回同じ指示を書く手間は、どれだけ減ったか
- 「推測させない」指示は守られていたか。勝手に展開・補完された箇所はなかったか
- 用語集を登録する前と後で、出力はどこが変わったか
- 用語集に載っていない語は、正直に「未登録」と返ってきたか
- 用語集に足すべきだと気づいた語は何か
- チームに共有するとしたら、何を追記する必要があるか。用語集ファイルは共有してよいものか
