| 項目 | 内容 |
|---|---|
| **目的** | 繰り返し業務を、指示を書いたエージェントとして固定する |
| **所要** | 約 20 分（目安） |
| **利用** | Copilot の Agent Builder |
| **入力** | AGT-00 で選んだ繰り返し業務 1 件 |

## シナリオ

[繰り返し業務を洗い出して1件に絞る｜AGT-00](./繰り返し業務を洗い出して1件に絞る_AGT-00.md) で決めた業務を、エージェントとして固定します。

候補としては、次のようなものが扱いやすいです。① 社内用語を維持した日英翻訳エージェント ② 会議メモを決定事項とアクションに変換するエージェント ③ ホワイトボード写真から構造化された資料案を作るエージェント ④ 社内の特定ガイドラインについて回答するエージェント ⑤ 定型文書をルールに沿ってレビューするエージェント。

以下は、**① を例にしたインストラクションの書き方**です。自分が選んだ業務が ①〜⑤ のどれであっても、書き方の型は同じです。「役割 → 出力の順序 → やってはいけないこと」の 3 段で書きます。

> ③ を選んだ方は、[ホワイトボード写真から議事録とスライドを作るエージェント｜AGT-02](./ホワイトボード写真から議事録とスライドを作るエージェント_AGT-02.md) で 1 日かけて深掘りします。ここでは別の候補で型を覚えてください。

翻訳を例にしたのは、**AI がいちばん勝手に補完したがるのが「用語」だから**です。社内略語や製品名を黙って展開されると、翻訳文は読めるのに業務では使えません。今日の見どころは、訳文の品質ではなく、**エージェントが「分からない」と言えるか**です。

> 進行役の説明例：「エージェントの出来より、『推測させない』指示が書けているかを見てください。」

## TRY — 手順

1. Agent Builder を開く（利用可否は事前に管理者へ確認）
2. AGT-00 で選んだ業務を 1 つ決める
3. エージェントの名前を決める（例：`社内文書の日英翻訳`）
4. インストラクション欄をクリックする
5. 次のインストラクション例を貼り付け、自分の業務に合わせて書き換える

> **インストラクション例（候補①：社内用語を維持した日英翻訳）**

```text
あなたは社内文書の日英翻訳エージェントです。
ユーザーが渡した日本語または英語の文章を、もう一方の言語に翻訳します。

【出力の順序】
1. 翻訳文
2. 翻訳せずに原文のまま残した用語の一覧（残した理由を1行で）
3. 訳し方に迷った箇所の一覧（候補訳を2つまでと、判断に必要な情報）

【翻訳のルール】
- 製品名、サービス名、チーム名、社内で使われている略語は、
  翻訳せず原文の表記のまま残してください。
- 意味が確定できない略語を、勝手に展開しないでください。
  例：「SA」を「Solution Architect」と断定しない。
- 原文にない情報を足さないでください。省略もしないでください。
- 箇条書き、見出し、番号は、原文の構造のまま保ってください。
- 敬語や丁寧さの度合いは原文に合わせてください。
  勝手に丁寧にしたり、くだけさせたりしないでください。

【口調】
- 補足の説明、感想、励ましは書かないでください。
```

6. エージェントを保存する
7. 実際の入力（自分の業務で使っている文章やメモ）を渡して動かす
8. 推測して補完された箇所がないかを確認する
   - 例（①の場合）：「原文のまま残した用語」と「迷った箇所」が、きちんと一覧で出ているか
9. 指示を修正して、もう一度動かす
10. 共有可否を管理者ポリシーに沿って確認する

> **書き換えのヒント**：①以外を選んだ場合も、`【出力の順序】` と `【〜のルール】` の枠はそのまま使えます。ルール欄には「**やってほしいこと**」ではなく「**やってはいけないこと**」を書くと、出力が安定します。

> **注意**：Agent の作成・共有可否や利用できる機能は、管理者設定、テナント構成、ライセンスによって異なります。公式ガイドでも、エージェントには利用可能な種類、共有ポリシー、管理設定があると案内されています。

## REFLECT — 振り返り

- 毎回同じ指示を書く手間は、どれだけ減ったか
- 「推測させない」指示は守られていたか。勝手に展開・補完された箇所はなかったか
- エージェントが「分からない」と正直に返した箇所はあったか
- チームに共有するとしたら、何を追記する必要があるか
