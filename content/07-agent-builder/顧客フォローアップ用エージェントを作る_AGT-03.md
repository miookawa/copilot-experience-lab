# 顧客フォローアップ用エージェントを作る｜AGT-03

| 項目 | 内容 |
|---|---|
| **目的** | 毎週繰り返す業務プロセスを、再利用可能なエージェントとしてパッケージ化する |
| **所要** | 約 20 分（目安） |
| **利用** | Agent Builder |
| **入力** | エージェント名・説明・指示・スターター プロンプト（＋許可されたナレッジ ソース） |
| **成果** | 動作する「Customer Follow-up Assistant」 |
> **実施条件**：テナントで Agent Builder が利用でき、必要なアクセス権がある場合のみハンズオンで実施します。
> 利用できない場合は、ファシリテーターのデモを見ながら、シナリオ・指示・スターター プロンプトを**設計演習**として確認してください。

---

## シナリオ

Lakeshore はここまで、Copilot Chat、Microsoft 365 Copilot、Researcher、Analyst をローンチ業務に使ってきました。
価値は見えてきましたが、同時にあるパターンにも気づいています。**これらのタスクの多くは、毎週繰り返される**ということです。

カスタマー サービスはフォローアップの準備をする。パートナーシップは提案書をレビューする。店舗オペレーションは未解決の質問を追う。マーケティングはメモを構造化されたドラフトにする。

毎回同じプロンプトを書き直す代わりに、チームは**繰り返しのワークフローを再利用可能なアシスタントにまとめる**ことにしました。

ここでのゴールは、複雑な本番ソリューションを作ることではありません。
**明確な目的、絞り込んだ指示、適切なナレッジ ソース、スターター プロンプト**が、よくあるワークフローを再利用可能なエージェント体験に変えることを理解するのがゴールです。

### SMB でよくあるエージェントの型

| エージェント | 適する対象 | 使い方の例 |
|---|---|---|
| Customer Follow-up Agent | 営業、アカウント管理、カスタマー サクセス | 顧客の状況、未解決のリスク、次のステップを要約する |
| Proposal Assistant Agent | MSP、コンサルタント、専門サービス、パートナーシップ | 提案書、SOW、顧客向けサマリーの作成を助ける |
| Service Operations Agent | サポート チーム、MSP、IT サービス | チケットを要約し、傾向を特定し、アクションを提言する |
| Security Readiness Agent | IT 管理者、MSP、規制対象の SMB | セキュリティ体制のサマリーとガバナンス上の次の一手を準備する |

### 作る前に自問すること

1. 改善したい**繰り返しの業務プロセス**は何か
2. 誰がこのエージェントを使うのか
3. エージェントはどの情報を使うべきか
4. エージェントが**決してやってはいけないこと**は何か
5. エージェントが一貫して生み出すべき成果は何か

> 最も成功するエージェントは、**特定のビジネス課題を、繰り返し、予測可能な形で**解決します。

## TRY — 手順

**Avery Howard**（カスタマー サービス）と **Hazel Rodriguez**（パートナーシップ）は、Spring Outdoor のローンチ中、顧客・ベンダー・社内関係者との頻繁なフォローアップに備える必要があります。
両チームが求める支援は同じ形です。直近の状況を要約し、未解決のアクションを特定し、リスクを示し、次の一手を提言する。
そこで Lakeshore は、再利用可能な **Customer Follow-up Assistant** を作ることにしました。

1. Microsoft 365 Copilot を開く
2. **エージェント** に移動する
3. **新しいエージェント／エージェントの作成**（表示名はテナントにより異なる）を選ぶ
4. 求められたら、手動で構成するか、構成画面へスキップする
5. エージェント名に次を使う

```text
Customer Follow-up Assistant
```

6. 説明に次を使う

```text
顧客、パートナー、プロジェクト、アカウントとのフォローアップ会話に備えるためのアシスタント。
直近の状況、未解決のアクション、リスク、決定事項、推奨される次のステップを要約します。
```

7. ナレッジ ソースは、**適切かつ許可されている場合にのみ**追加する
   （例：顧客メモ、会議サマリー、アカウント プラン、プロジェクト トラッカー、提案書、`agent-knowledge-pack.docx`）
8. 指示（インストラクション）に次を使う

```text
あなたは SMB 組織向けの顧客フォローアップ アシスタントです。
ユーザーが顧客・パートナー・プロジェクト・アカウントとの会話に備えるのを支援してください。

回答する際は、直近の状況を要約し、未解決のアクションを特定し、リスクやブロッカーを示し、
次に取るべき最善のアクションを提案し、出力は簡潔でビジネスにすぐ使える形にしてください。

ユーザーがアクセスできる情報のみを使ってください。
情報が不足している場合は、どんな追加コンテキストがあれば役立つかを述べてください。
顧客に関する事実、コミットメント、価格、日付、決定事項を創作してはいけません。
```

9. スターター プロンプトに次を追加する

```text
a. [顧客／パートナー／プロジェクト] との次の会議に向けて準備してください。
   直近の状況、未解決のアクション、リスク、私が答えられるようにしておくべき質問を要約してください。

b. [顧客／パートナー／プロジェクト] の最新の動きを要約し、フォローアップ アクションの
   上位 3 件を提案してください。

c. [顧客／パートナー／プロジェクト] に関連するリスク、ブロッカー、未解決のコミットメントを
   特定してください。

d. 直近の議論と未解決のアクションをもとに、[顧客／パートナー／プロジェクト] 向けの
   簡潔なフォローアップ メールを作成してください。
```

10. エージェントを保存／作成する
11. 次の安全なシナリオでエージェントをテストする

```text
Spring Outdoor 共同マーケティング提案について、Northwind Outfitters とのフォローアップに
向けて準備してください。

直近の状況: Northwind は有料ソーシャル費用の 35% 負担を提示し、ローンチ週のホームページ掲載を
要請しており、SKU 単位の最終的な在庫コミットメントはまだ提出されていません。
Lakeshore 側は、サイネージの期限、トレーニング用サンプル、キャンペーンの効果測定を
確定する必要があります。

状況、リスク、未解決のアクション、そして私が聞くべき質問を要約してください。
```

12. 応答が簡潔で、根拠があり、有用で、**不足しているコンテキストを明示している**かを確認する

## REFLECT — 振り返り

- 「してはいけないこと（事実・価格・日付を創作しない）」を明記したことが、応答の質にどう効いたか
- スターター プロンプトがあることで、他のメンバーはどこまで迷わず使えるか
- 自社で最初に作るなら、どの繰り返し業務をエージェント化するか

**セクションの学び**
役に立つエージェントには、**明確な目的、絞り込んだ指示、適切なナレッジ ソース、意図したワークフローへ導くスターター プロンプト**が必要です。
